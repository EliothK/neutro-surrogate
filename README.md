# neutro-surrogate

A neural surrogate for the 1-group neutron diffusion eigenvalue problem in a multi-zone 1D slab reactor.

The physics reference is a finite-volume solver (`src/solver.py`) that finds the fundamental eigenpair `(k, phi)` of

```
-d/dx [ D(x) dphi/dx ] + Sa(x) phi(x) = (1/k) nSf(x) phi(x)
```

with zero-flux boundary conditions, via `scipy.sparse.linalg.eigs` on a banded system.
This solve is the ground truth used to train and evaluate a PyTorch MLP (`src/model.py`) that maps slab/material parameters directly to `(k_eff, flux profile)`, optionally regularized by the diffusion-equation residual itself (`src/physics.py`) as a physics-informed loss term.
`src/hybrid.py` then turns the predicted flux into `k` by a Rayleigh quotient and re-fits it with a cheap Rayleigh-Ritz step; with no solver calls this gets `k` to within a few pcm RMSE at about 25x the solver's speed in batches (see step 8 below).

## Project layout

```
src/
  config.py     central configuration: parameter ranges, geometry, paths
  sampling.py   Latin hypercube design of experiments over the parameter space
  solver.py     finite-volume diffusion solver (ground truth, via ARPACK)
  physics.py    banded-operator residual used as the physics-informed loss
  model.py      SurrogateMLP network + input Normalizer
  train.py      training loop (data-only or physics-informed)
  baseline.py   non-neural baselines (ridge regression, gradient-boosted trees)
  benchmark.py  accuracy metrics, baseline comparison, and timing/speedup
  hybrid.py     surrogate flux + Rayleigh-quotient k, inverse-power refinement, Rayleigh-Ritz amplitude re-fit, residual gate to the solver
  plots.py      regenerates the figures in figures/
  make_dataset.py  builds data/dataset_rescaled.npz: LHS design -> solve -> criticality -> rescale -> train/val/test split
  pipeline.py   runs the whole thing end to end (see "Run everything" below)
tests/          pytest suite for the solver, physics residual, sampling and hybrid prediction
data/           generated datasets (.npz)
models/         trained model checkpoints (.pt)
results/        metrics_<variant>.json output from benchmark.py
figures/        plots generated by plots.py, one folder per variant
```

Each input sample is a 16-zone slab described by a 49-dimensional vector: slab width, plus per-zone diffusion coefficient, absorption cross section, and fission-neutron-production. Zone counts, ranges and the cell grid live in `src/config.py` (`N_ZONES = 16`, `N_CELLS = 192`).

Samples come from a Latin hypercube (`src/sampling.py`). Each property is drawn at `PROFILE_KNOTS = 5` points and linearly interpolated onto the zones, so profiles are smooth in space (`--n-knots 0` gives independent zones). Independent zones made the eigenvalue nearly unlearnable, so smooth profiles are the default.

Two dataset variants are built and benchmarked:

- `rescaled`: fission is rescaled so the solved eigenvalue lands exactly on a target `k` drawn uniformly from `(0.90, 1.10)`. Rescaling moves fission outside its sampled range `(0.02, 0.16)` for about 8% of fuel-zone values, giving an effective range of roughly `0.004–0.18`.
- `natural`: parameters are kept as drawn and a sample is accepted only if its `k` falls in `NATURAL_K_RANGE = (0.5, 1.5)`.

## Run everything

```bash
python -m src.pipeline
```

This runs the whole thing in order: tests, then for each variant (`rescaled`, `natural`): generate `data/dataset_<variant>.npz` -> train the data-only surrogate -> train the physics-informed surrogate -> benchmark both against the solver and the non-neural baselines -> regenerate the figures into `figures/<variant>/`. Useful flags:

```bash
python -m src.pipeline --n-samples 5000 --epochs 50   # quick smoke run
python -m src.pipeline --skip-tests --skip-dataset     # reuse existing datasets, retrain/rebenchmark/replot only
python -m src.pipeline --variant natural --k-min 0.7 --k-max 1.3 --seed 1
python -m src.pipeline --n-knots 0                     # independent zones instead of smooth profiles
```

Defaults come from `src/config.py` (`DEFAULT_N_SAMPLES = 30000`, `DEFAULT_SEED = 62922`, 200 epochs). A full run with the defaults generates 30k solved samples and trains two networks per variant; pass `--n-samples`/`--epochs` to shrink it for a quick check.

## Running the steps individually

All commands are run as modules from the project root so relative imports in `src/` resolve correctly.

**1. Run the tests** (covers the solver, physics residual, sampling, model and cross-validation folds):

```bash
pytest
```

**2. Generate the dataset.** Draws a Latin hypercube design, solves each sample with the finite-volume solver, rescales it to a target eigenvalue (`rescaled` mode) or filters on `k` (`natural` mode), and writes train/val/test splits.

```bash
python -m src.make_dataset --n-samples 30000 --seed 62922 --mode rescaled --out data/dataset_rescaled.npz
# --mode natural --k-min 0.5 --k-max 1.5 for the wide-band variant
```

**3. Train the surrogate:**

```bash
# data-only baseline
python -m src.train --data data/dataset_rescaled.npz --epochs 200

# with the physics-informed residual loss
python -m src.train --data data/dataset_rescaled.npz --epochs 200 --physics
```

Add `--out models/<name>.pt` to choose the checkpoint path (the pipeline writes `models/surrogate_<variant>_data_only.pt` and `..._physics.pt`).

Other training options (defaults keep the original behaviour):

- `--flux-loss {mse,shape,blend}`: `mse` is cell-wise MSE on the peak-normalised flux; `shape` compares L2-normalised profiles; `blend` is their sum.
- `--zone-head`: adds a per-zone log-amplitude, interpolated onto the cells and multiplied into the flux, so the power split between fuel regions has its own outputs.
- The CLI restores the weights with the best validation eigenvalue error; `--no-keep-best` keeps the last epoch instead, and `--patience N` stops after `N` epochs without improvement.

These options are off by default because their effect depends on the dataset (tuned physics configs, trained on train only, two seeds):

- On the rescaled test split, `--zone-head --flux-loss blend` cut the median flux relative L2 error from 0.83% to 0.62% and the mean from about 2.1% to 1.9%.
- On the natural test split it made every flux metric worse (flux R^2 0.965 vs 0.971, mean relative L2 4.3% vs 3.8%) and raised the direct `k` RMSE from about 510 to 590 pcm.
- On the out-of-distribution sets the results were mixed: better flux MAPE, but a heavier Rayleigh-quotient `k` tail.

Neither option was part of the hyperparameter search, so treat them as candidates to tune per dataset rather than as improvements.

**4. Benchmark the trained surrogate(s)** against the direct solver and the non-neural baselines (ridge regression, gradient-boosted trees), including timing/speedup:

```bash
python -m src.benchmark --data data/dataset_rescaled.npz --model models/surrogate_rescaled_data_only.pt --physics-model models/surrogate_rescaled_physics.pt --results results/metrics_rescaled.json
```

Writes the file given by `--results`.

**5. Regenerate figures:**

```bash
python -m src.plots --data data/dataset_rescaled.npz --model models/surrogate_rescaled_data_only.pt --fig-dir figures/rescaled
```

Writes to `--fig-dir`.

**6. Cross-validation.** K-fold CV over the train + validation pool (the test split is never used). Every fold trains a fresh model and fits its own normaliser and loss scales on that fold's training part only, so nothing leaks. Reports the mean and standard deviation across folds. Folds are shuffled (not walk-forward) because the samples are independent.

```bash
python -m src.crossval --data data/dataset_rescaled.npz --folds 5
python -m src.crossval --data data/dataset_rescaled.npz --from-tuning results/tune_dataset_rescaled.json --test
```

`--test` then refits on the whole pool and scores the test split once. Use it only for the final configuration.

**7. Cross-validated hyperparameter tuning** (Optuna). Needs `pip install optuna`. Searches 13 variables jointly, with `train_fraction` left at 1.0 (it is a data-size diagnostic, not a tuning knob):

- training loop: `epochs`, `lr` (log scale), `batch_size`, `scheduler` (cosine / linear / none), `grad_clip`
- network: `width`, `depth`, `activation` (silu / relu / gelu / tanh), `dropout`, `weight_decay` (log scale)
- loss: `lam` (flux-loss weight), and with `--physics` also `mu_max` and `ramp_frac`

The sampler is TPE (multivariate) with a median pruner. Every trial is scored by `--folds`-fold cross-validation (default 5) as the mean over folds of the eigenvalue and flux median errors, each divided by the same errors of the default config, so 1.0 means "same as the defaults". Trials that fall behind the median after a fold are pruned. The default config is also run with two extra seeds to measure run-to-run noise, and the winner only replaces the defaults if it beats them by more than that noise. The test split is used once, at the end, on the chosen config refit on the whole pool.

```bash
python -m src.tune --data data/dataset_rescaled.npz
python -m src.tune --data data/dataset_natural.npz --physics --trials 30 --folds 3
python -m src.study                                   # all four combinations back to back
python -m src.study --folds 3 --trials 30             # cheaper
```

Trials are stored in SQLite (`results/optuna_<dataset>[_physics].db`), so a crash or restart loses at most the trials in flight; rerun the same command to resume (`--trials` is the total wanted, resumed trials count). Pass `--fresh` to start over and `--timeout-hours` to cap wall-clock time. Outputs: `results/tune_<dataset>[_physics].json` (best config, CV mean and std, test metrics, noise margin), a trials CSV beside it, and `figures/tuning/<dataset>_{history,importance,folds}.png`.

Cost: each trial is `--folds` trainings, and the search space allows up to 800 epochs and width 768, so trials vary a lot in length. Use fewer folds or trials, or `--timeout-hours`, to bound it.

**8. Hybrid prediction.** The operator is symmetric, so `k` computed from the predicted flux by a Rayleigh quotient has an error quadratic in the flux error, far below the network's own eigenvalue head. `src.hybrid` adds these stages on top of the network:

- Rayleigh-quotient `k` and the relative residual `||A phi - F phi / k|| / ||F phi / k||` of the predicted flux.
- `--refine N` inverse-power steps, each one tridiagonal solve; they converge as `k2/k1`, so they cannot fix near-degenerate cores.
- `--ritz M`: a Rayleigh-Ritz step over the predicted flux times `M` hat functions, then one more inverse-power step. It keeps the network's shape within each hat and re-fits the amplitudes between them, which is exactly what goes wrong in near-degenerate cores. It is variational, so its `k` never exceeds the true `k` and never falls below the plain Rayleigh quotient.
- A residual gate: the threshold is set on the validation split so that a `--fallback` fraction of samples fails it, and those samples are solved exactly instead.

```bash
python -m src.hybrid --model models/<checkpoint>.pt --data data/dataset_rescaled.npz --refine 1 --fallback 0.02 --timing
```

It writes the full metric report (and, with `--timing`, per-stage cost against the solver) to `results/hybrid_<checkpoint>.json`. Calibrate on a split the model did not train on: checkpoints from `src.final` were trained on train + validation, and the script warns if you calibrate one of them on validation.

Test-split results for a zone-head + blend model (batch of 3000 on a GTX 1080 Ti, where the solver takes about 0.73 ms per sample):

| fallback to solver | flux rel-L2 mean | k RMSE | k MAE | speedup vs solver |
|---|---|---|---|---|
| none (network, direct k) | 1.9% | 179 pcm | 105 pcm | about 1000x |
| none (refine 1, Rayleigh k) | 1.6% | 66 pcm | 6.6 pcm | about 190x |
| 1% | 1.2% | 49 pcm | 3.8 pcm | about 50x |
| 2% | 0.9% | 33 pcm | 2.4 pcm | about 30x |
| 5% | 0.7% | 2.8 pcm | 1.0 pcm | about 15x |

The solver calls set the cost, so the speedup is capped near `1 / fallback`. For a single sample the hybrid is no faster than the solver, since per-call overhead dominates at that size.

Pass `--eval-data` to score a different dataset with the threshold still set on `--data`, for example an out-of-distribution set:

```bash
python -m src.hybrid --model models/<checkpoint>.pt --data data/dataset_rescaled.npz --eval-data data/ood_rescaled.npz --refine 1 --fallback 0.02
```

Results across datasets (2% gate calibrated on in-distribution validation, MSE-loss models, two seeds):

| evaluated on | direct `k` RMSE | Rayleigh `k` RMSE, no gate | Rayleigh `k` RMSE, gated | sent to solver |
|---|---|---|---|---|
| rescaled test | 171 to 177 pcm | 84 to 95 pcm | 7 to 52 pcm | about 2% |
| rescaled OOD | 3900 to 4200 pcm | 820 to 950 pcm | about 21 pcm | 17 to 18% |
| natural test | about 510 pcm | 200 to 220 pcm | 130 to 145 pcm | about 2% |
| natural OOD | about 6000 pcm | 1470 to 1600 pcm | 250 to 360 pcm | about 18% |

The Rayleigh-quotient `k` beats the direct head on every set.
The gate fails safe: a threshold that flags 2% of in-distribution samples flags about 18% of out-of-distribution ones by itself, trading speed for accuracy there.
The natural dataset has a much heavier flux tail (relative L2 p99 above 110%), and the residual gate recovers less of it.

**Ritz re-fit (recommended).** The worst Rayleigh-quotient errors all underestimate `k`, with the power in the wrong region and a small residual, so no residual threshold catches them; re-fitting the amplitudes fixes them without calling the solver. Use `M = 17` or `M = 33`: those put hat nodes on the 16 zone boundaries, and misaligned values (25, 32) do clearly worse out of distribution.

```bash
python -m src.hybrid --model models/<checkpoint>.pt --data data/dataset_natural.npz --refine 1 --ritz 17 --fallback 0 --timing
```

Results with no gate and no solver calls (MSE-loss models, two seeds, batch of 3000 on a GTX 1080 Ti):

| | rescaled test `k` RMSE | natural test `k` RMSE | rescaled OOD `k` RMSE | natural OOD `k` RMSE | flux rel-L2 mean (test) | speedup vs solver |
|---|---|---|---|---|---|---|
| refine 1, no Ritz | 84 to 95 pcm | 204 to 222 pcm | 820 to 950 pcm | 1470 to 1600 pcm | 1.8 to 3.6% | about 200x |
| refine 1, Ritz `M = 17` | 1.5 to 2.3 pcm | 4.6 to 7.5 pcm | 35 to 40 pcm | 24 to 28 pcm | 0.18 to 0.28% | 25 to 28x |
| refine 1, Ritz `M = 33` | 0.3 pcm | 0.5 to 0.7 pcm | 4 to 7 pcm | 1.9 to 2.3 pcm | 0.03 to 0.07% | 7 to 8x |

`M = 17` beats the 2% residual gate on both accuracy and speed, and it keeps its speed out of distribution, where the gate sends about 18% of samples to the solver.
`M = 33` runs its small eigenproblems on the CPU, because batched GPU `eigh` is about 25x slower than the CPU above 32 x 32 on this setup.
The network still matters: started from a flat flux instead, the same `M = 17` pipeline gives `k` RMSE of about 260 to 290 pcm.
